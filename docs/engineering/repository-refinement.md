# Repository refinement

Add `refine` to an owner-authored issue. `lighthouse-sdlc-router.yml` authorizes the event and calls the gh-aw refinement worker. An owner reply to a pending `needs-info` question resumes that stage. SoFa observes GitHub evidence independently; its service and database are not needed.

The issue and explicit owner answers are the product-intent record. ProductShape and ArcShape are not installed authorities here. Refinement defines scope and acceptance criteria; `ready` never grants implementation or merge authority.

Open the Actions run linked from the result comment. Preparation verifies the request and reserves the issue with `agent-working`. For live progress, open `refine / agent` → `OpenCode progress and result`. It shows public agent updates, one-line tool activity, elapsed-time notices during quiet intervals and the validated result. The other jobs prepare, authorize, publish and close the execution; they are not separate agent assignments. The agent job summary contains the refinement result. Download `opencode-events` for redacted structured diagnostics, gh-aw artifacts for session and usage evidence, and the Lighthouse result artifact for the envelope and runtime receipt. Publication validates the result and rereads source and owner answers before setting `ready` or `needs-info` and releasing the reservation. Artifacts follow GitHub retention and are not a permanent archive.

Bastion provides a dedicated runner container labelled `lighthouse-workflow`. Each engine invocation uses a temporary container with read-only source and packaged skills. Runtime authentication remains operator-owned. The Docker subscription profile has outbound networking and does not provide AWF egress filtering or credential proxying. The workflow pins its Lighthouse implementation independently of the foundation version. Update it with the SDLC package's `install-workflows.mjs`, then commit the reviewed sources and compiled lock together. `LIGHTHOUSE_AUTOMATION_ENABLED` is the repository execution switch.

To take over active work, add `human-working` and cancel or wait for the Actions run. That label reserves work; `needs-info` means waiting for an answer. Labels cannot lock out arbitrary editors. A changed issue, answer or source prevents publication. Inspect failed runs before retrying or clearing a stale `agent-working` reservation. After three unresolved answer rounds, add `refine` explicitly to request another attempt.

This repository enables only refinement. Catalogue verification and Lighthouse guardrails remain separate CI checks. Later delivery stages need their own authorized workers; this setup does not implement the talk migration in issue 18.
