## Observations

- The implementation uses React/Vite, Three.js, React Three Fiber and GSAP. It is custom application code without Slidev or another packaged presentation framework. “Independent of a presentation framework” therefore does not imply zero application or animation dependencies. ([Manifest](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/package.json))
- The screenshots show a dark canvas, large white display type, small monospace annotations, restrained blue accents and geometric forms rendered as point clouds. The system view connects the narrative to a spatial diagram rather than a repeated title-and-bullets layout. Those observations establish a visual reference, not an approved design for our talks. ([Cover](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/artifacts/rebuild/cover-es.jpg), [system view](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/artifacts/rebuild/system-es.jpg), [art direction](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/docs/art/art-direction.md))
- The architecture models presenter-controlled stops on a timeline. Input advances a target; a playhead determines scene state. DOM and graphics share that position, and URL hashes preserve a stop for reloads. This is a useful design pattern to evaluate; adopting its entire engine is unnecessary. ([Architecture](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/docs/architecture.md))
- The documented controls include forward/back keys, clicker-compatible PageUp/PageDown and fullscreen. The source filters typing targets, modifier keys and repeated navigation presses. Our proposal must also protect focused links, buttons and embedded controls; observing this reference does not prove its accessibility or ours. ([Input source](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/src/engine/input.ts))
- The performance guidance describes reduced-motion cuts and readable DOM/SVG fallback when WebGL is unavailable. Static publication uploads a Vite `dist` build. These are candidate implementation and test considerations, not measured guarantees. ([Performance](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/docs/performance.md), [deployment](https://github.com/CKGrafico/platform-slides/blob/1eed250713a65be23dba3e821e8edfa3b8024e97/.github/workflows/deploy-pages.yml))

## Proposal boundary

Use this inspection to compare original visual and interaction approaches for the two existing talks. Reuse of our current React/Vite application tooling is within the refined scope; adding Three.js or GSAP needs a concrete benefit and a fallback/test plan. The proposal should choose a bounded design and leave final visual/content acceptance to the owner after a rendered preview.

No repository license file was found at the inspected revision, and GitHub reported no detected license. No code, shaders, images, fonts or other assets from that repository were copied into this project. Plan an original implementation; any later decision to copy reference material requires a separate reuse-rights check. This note supplies offline research context for the sandboxed proposal worker and introduces no dependency on the reference repository.
